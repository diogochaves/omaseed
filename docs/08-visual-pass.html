1 · The mark · B1.1

An icon on the seed idea that holds up at 16 px

The tray is 16–22 px in the Omarchy bar, so every candidate is judged there first. Each row shows the five tray states at 22 px, the same mark at 16/22/32 px, and the 128 px launcher size.

found

All five tray states are the same diamond (src/integration/resources/tray/*.svg). Downloading and alt-speed also get a painted badge, but error is colour only: a red diamond. On Hackerman, red is #50f872, so the error icon is green. The launcher icon (data/icons/…/omaseed.svg) is still the T1.5 placeholder, a rounded square in fixed Tokyo Night blue that looks nothing like the tray mark.

proposed

Whatever mark you pick, every state gets a shape, not just a colour: a count badge for downloading (as today), a slow badge for alt-speed (as today), an ! badge for error (new), and an outline for disconnected (as today). All the candidates below are drawn this way, so the states are readable on any theme.

Fig. 1.1: Each candidate in a bar strip at 16 and 22 px, idle and downloading. The neighbours are generic bar icons at the same weight, so you can see which mark disappears and which shouts.
Fig. 1.2: Launcher size (128 px, shown at 96). The launcher icon can't follow the theme, so it gets one fixed palette at implementation. It's drawn here in the current theme's accent only to compare shapes.
2 · How omaseed draws symbols · B1.4c

The gear is a symptom: 8 of 24 glyphs are drawn by a font we didn't choose

The UI font is whatever fontconfig answers for monospace (src/integration/Theme.cpp:226), and a font change in Omarchy moves it. Today that's JetBrainsMono Nerd Font. The table audits every non-ASCII glyph in Kit/Glyphs.qml against it.

Fig. 2.0: Coverage is from fc-list :charset=… on this machine. * JetBrains Mono does have ⌨, but ⌨ is emoji-capable and was seen drawn in colour during the batch-1 capture, like ⚙. Qt prefers the emoji font for these codepoints, and U+FE0E doesn't override it.
Fig. 2.1: The four fixes, each applied to the hero's actions and the settings nav. "Now" reproduces the bug: the page asks for the colour emoji font the way fontconfig does for Qt. Option B is drawn with Material Symbols because the page can load it. The installed alternative is the Nerd Font symbol set.
Fig. 2.2: What option A can actually use. None of these is emoji-capable, and JetBrainsMono NF has each one. None of them means "settings" or "keybindings" the way ⚙ and ⌨ do, and that's the problem with A. The red-framed pair is today's.
recommend

D, with a rule: icons are SVG and typographic symbols stay text. Draw a small Kit/Icon.qml set (gear, keyboard, alt-speed, server, appearance, jump, category, checking, plus the new more/columns/sidebar) and tint it through Theme roles like any glyph. Keep the arrows, ✓ ■ ● ◆ and friends as text, because they sit inside running text and every mono font has them. This fixes all eight, adds no dependency and survives a font change. C is the same work plus about sixteen more icons, for consistency you may not need.

3 · The hero / top bar · B1.3, B1.4

Connection status, alt-speed, a real menu, and a + you can see

These all compete for the right-hand side, so they're drawn together. Every variant from here on uses the §2 recommendation, so the gear is a monochrome SVG in its Theme role.

found

There is no ▾ menu. The second hero button, ⏷ (U+23F7), is the alt-speed toggle (Kit/Hero.qml:175). It looks exactly like a dropdown chevron, which is why alt-speed looked like it was hidden inside something. It's also one of the eight glyphs from §2 that JetBrains Mono doesn't have.

Fig. 3.1: Today, while the playground is firewalled. The dot is green and the line says nothing: GlobalState::connectionStatus is parsed and never drawn. The colour gear outshines the accent + beside it.

Alt-speed and the actions around it

Fig. 3.2: The ⋯ menu, opened with ctrl+. or a click. It's where the global limits and the new server features live. The dim rows are features the API has (verified live on :8081) that we don't implement yet. Each is its own task, and a row only appears once its feature ships.
Why a menu, and why these rows
The hero has room for four icons, and three of them are taken. Everything else that's global and occasional (setting the limits, not just toggling them, creating a torrent, search, export) needs one home that's findable with the mouse and teaches its key. Columns and select-all are listed because you couldn't find them (B1.5, B1.14a). They keep their keys, and the menu is where the keys get taught. Row order is frequency, not feature age.

4 · The help sheet · B1.11b

Strata's structure in our chrome: sections, a sentence per key, a filter

Same data as Fig. 26 plus the rulings: ctrl+, joins , on Settings, F1 is shown next to ? (shipped in 18247e5), and Columns gets its new key. Nothing is copied from Strata. Only the shape is borrowed: grouped sections, a description beside each key and a scrollable body.

Fig. 4.1: Today (Fig. 26). Chips and two-word glosses. Columns is filed under "app" as ctrl+,, where nobody looks for it.
Fig. 4.2 · layout A recommended: One sheet in two balanced columns with a filter on top. Typing narrows every section at once. Shown with the filter at col. The first match gets the cursor, and enter runs it, so the sheet doubles as a command list.
Fig. 4.3 · layout B: Settings-shaped, with sections on the left and one section at a time. It's closer to Strata and roomier for descriptions, but you can't scan everything at once, which is most of what a cheat sheet is for.
