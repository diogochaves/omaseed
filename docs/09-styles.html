Four styles from four reference boards. Same app, same colours, different form

Each style is drawn from one of the boards in .local/. It borrows the board's grammar: type, containers, spacing, ornament, and how state and selection are drawn. It doesn't borrow the board's palette or its marks. Every colour here is an Omarchy role, so switch the theme above and all five follow. v2 stays the default and doesn't change. A style is a setting under Appearance.

The boards' brand names (ARC, TRA, D350) belong to someone else's work, so each style gets a working name of our own: Label, Console, Pass and Mission. Items marked deviation bend a v2 §3 rule. The decision sheet at the bottom collects your answers into one paste.

1 · The four grammars

What each board teaches, once its colour is taken away

A style is about ten decisions, and every screen follows from them. Writing them down first is what keeps a style consistent across the app's ~40 views instead of becoming a pile of tweaks. Each card shows the style's display face and its signature detail, drawn in your current theme.

4 · How it's built

A Style singleton for tokens, Qt file selectors for the rest

Theme stays exactly what it is: what Omarchy says (colours, base size, font, radius). A new Style singleton holds the form tokens from §1's table. Where a style needs different structure, not only different values, it ships its own version of a Kit component in a +style folder. QQmlFileSelector picks that version, and views keep writing Hero {} without knowing which one loaded. Changing the style reloads the engine, which takes about a second and keeps your selection and filter.
