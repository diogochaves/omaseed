§1 · rule these

Twelve items that need your call

J = design call · D = scope · S = spec. The numbers match docs/UX-NOTES.md.

J1

The right-docked details panel is too narrow for its lists

  • Files: both bbb_sunflower_… rows read the same, so you can't tell which one you're prioritising.
  • Trackers: two different trackers both read tracker.examp…, and the status is cut to "timed out · retr…".
  • Peers: addresses are cut to 185.21…, and clients to qBittorre….
  • The rail's tracker hosts have the same eliding problem, which is still open.

Recommend: both. Elide in the middle so the ends survive (bbb_sunf…1080p.mp4, tracker.…org), show the full text on hover as in B1.8, and make the default panel wider. Middle eliding alone can't fix the peers' client column.

J2

Column headers in the details lists don't line up with their rows

  • In Trackers and Peers, the headers sit to one side of the text below them, because each row starts with a status dot or a fold arrow that the header doesn't have.
  • Peer speeds read 1.02 M while the main table says 1.02 MB/s.

Recommend: line each header up with its row text and use the table's units. If a unit doesn't fit, that's a J1 problem, not a reason to shorten it.

Screenshots: the Trackers and Peers images in J1.
J3

The settings window changes height as you move between pages

  • Its minimum is 470 units and it grows to fit the page on show. Going from Notifications to Appearance with j moves its top edge up by about 95 px.
  • Short pages (General, Servers, About) leave a large empty area; Appearance is the tallest.

Recommend: a fixed height, set by the tallest page and capped at 85 % of the window, with the page scrolling (and showing a scrollbar) when it's over the cap. The window then stays still while you move through it.

J4

Settings › Keybindings repeats the ? sheet

  • It is the same component with the same rows, and it's read-only. It can't drift from ?, but a Settings page you can't change anything on reads like a promise it doesn't keep.

Recommend: keep it as it is for v1 (people look for keys in Settings) and add a line at the top: "Rebinding comes later. ? shows this anywhere." Rebinding goes on the v2 list.

J5

Inline rename shows the end of the name, not the start

  • The editor is only as wide as the Name cell, so a long name opens scrolled to its end (…6.09.01-x86_64.iso) and you can't see what you're renaming.

Recommend: while editing, the field widens over the next columns (up to the table's width) and scrolls to the start, with the whole name selected. The table goes back to normal when you press enter or esc.

J6

An empty field goes blank when you focus it, so you lose the "unlimited" hint

  • The field hides its placeholder on focus, so in Limits and Speed limits, Download reads as blank while Upload beside it says ∞. The two mean the same thing, but the first looks like a missing value.
  • Share ratio in Limits has no placeholder at all.

Recommend: keep the placeholder until you type, dimmed a step further while focused (as most text fields do). Give share ratio an ∞ placeholder too.

J7

The delete confirmation shows the name twice and wraps it mid-name

  • The title is "Delete "archlinux-2026.09.01-
    x86_64.iso"?", and the line under it repeats the name with the size.

Recommend: title "Delete this torrent?" (or "Delete 3 torrents?"), with the name and size once below it. With several, list the first three and "and 5 more".

J8

Five small wording and consistency fixes

  • Set location's hint is a bare ctrl+o; Add says ctrl+o browse. → add "browse".
  • About shows the Qt version twice (VERSION and QT). → drop "(Qt 6.11.2)" from VERSION.
  • General: "Off hides the multi-server chrome." → "Off hides it until you add a second server."
  • Appearance: Rail scroll hint and Tracker hosts have a plain dot where the other rows have an icon. → give them icons.
  • The details header cuts the added date ("added 11 Sep 1…") while it still shows every tag. → shorten tags first; the date stays whole.

Recommend: apply all five.

D1

What else belongs in the add sheet for v1?

  • Today it has the source, category, tags, save path, layout, upload limit, sequential download, and skip hash check.
  • qui and qBittorrent's own dialog also have: choosing files and priorities before adding, a download limit, rename, and first and last pieces first.
  • The API takes download limit, rename and first/last pieces directly on add, so each of those is small. The file picker is the big one: a .torrent has to be read locally, and a magnet only has a file list after its metadata arrives, so for magnets it has to come after adding.

Recommend: all four, with the file picker for .torrent files only in v1. Magnets get it in v2, through "add stopped, then choose files".

D2

"alt-speed limits…" in the ⋯ menu opens the plain Speed limits sheet

  • It's the same sheet with the alt-speed fields focused, still titled "Speed limits · the server's global limits".

Recommend: keep one sheet, but when it's opened from that entry, title it "Alt-speed limits" and say what they are ("used while alt-speed is on, A"). That's cheaper than a second sheet and less surprising.

D3

Should the add flow's hints appear twice?

  • With the add sheet open, "tab fields · enter add · shift+enter add stopped" shows at the bottom of the sheet and in the window footer. With help open, the footer has both "esc close" and "esc clear, then close".
  • Batch 1 made the window footer the place hints live. Sheets kept their own row from v2.

Recommend: when a sheet or modal is open, the window footer shows only the facts on the left, and the sheet's own row is the only place for hints.

S1

The help sheet says 0–9 for status filters, but 9 does nothing

  • The rail has nine status rows, 0 (all) to 8 (errored). The spec's Fig. 26 prints 0–9, and the spec is never edited, so either choice is logged as a deviation in REVIEW-v0.1.0.md §9.

Recommend: print 0–8. The help should match the keys. A spare 9 is fine and can get a job later.
