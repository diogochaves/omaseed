Make the file filter findable, and fill the details panel like the clients people know

You said nothing tells you / filters the files, and that esc didn't close it. The esc part was a bug and it's fixed. This board is about the rest: how to make the filter visible, and what else is worth adding to the panel. For that I looked at qBittorrent, qui, VueTorrent, Transmission, Deluge, BiglyBT, Fragments, Flood, Tixati, Motrix and µTorrent. §1 · finding the filter

Why you can't see it today

The only hint is / filter in the footer, and the footer shows it only while the details panel has the keyboard. With focus on the table, the footer lists the table's keys, and there / searches torrents. So nothing on screen says files can be filtered until you've already found it.

F1

Where the filter lives

Almost every client with a file filter keeps a field above the list at all times: qBittorrent ("Filter files…"), qui ("Search files…" with a live "3 of 12"), VueTorrent, BiglyBT. Fragments hides it behind a magnifier button. Transmission GTK and Deluge only have hidden type-ahead that jumps to a match, and nobody finds it.

  • A. Summary line. One quiet line above the headers gives the facts about the files (count, folders, size, skipped) and ends in ⌕ filter /. Clicking it or pressing / turns the line into the field; esc turns it back. It costs one row, which it pays for with the file count you asked for, and it matches the head strip's facts-first tone.
  • B. Always-visible field. The qBittorrent and qui way: an empty field with a placeholder, always there. It's the most familiar, but it's a boxed control sitting over the list all the time, and it doesn't carry the count.
  • C. A chip in the tab strip. ⌕ / at the right end of the tab row, as qBittorrent's WebUI does. It costs no row, but it's the easiest to miss, and there's no room for it with the tab strip at narrow widths.

In all three, the footer keeps / filter while the panel has focus, and the field shows n of m files as you type.

Recommend A. It gives the count you wanted and makes the filter visible without a permanent empty box. It's the same row whether you're filtering or not, so the list never jumps.

Single-file torrents

An .iso or a single .mkv has one file, so there's nothing to filter. Transmission on macOS disables its filter for single-file torrents.

Recommend the summary line reads 1 file · 1.31 GB with no ⌕ filter /, and / does nothing there. (Pressing it flashes "one file, nothing to filter" in the footer, so the key doesn't seem broken.)

F3

Acting on what the filter shows

The main reason to filter a file list is to do something to the matches: skip every .nfo, raise every episode of a season. qBittorrent does it with filter, then select all, then a priority. VueTorrent has a bulk-select dialog. Today you can filter, but then have to space each match one by one.

Recommend ctrl+a in the Files tab selects every file the filter shows (folders count through their files), and the footer says 2 selected. Then p, or + - x, act on them as they already do. With no filter it selects every file.

F4

How a filter matches

Today it's a plain substring of the name, ignoring case. qBittorrent adds a right-click menu for wildcards, regex or plain text. BiglyBT has a small language documented in a tooltip: | for or, ! for not, p: for the full path, a regex toggle, and size:>1G.

  • Plain, plus * and |. *.srt and mkv|mp4 cover almost every real case. The placeholder can say so: filter files · *.srt · mkv|mp4.
  • Plain only, as today.
  • BiglyBT's full language. Powerful, but it needs a tooltip to explain it, and nobody reads those.

Recommend plain + * + |, matched against the path so subs/ finds a folder's files.

§3 · the General tab

From a flat list to three groups, with a pieces bar

Today General is one list of 15 rows in the order the code adds them. Status sits between the hash and the byte counts, and nothing groups what belongs together.

G1

Group the rows

Transfer covers what's moving: status, downloaded, uploaded, wasted, seeds, peers, connections, availability, speeds and times. Information covers what the torrent is: size, pieces, save path, hashes, magnet, created by and on, completed on, comment. Options covers what you can change: limits, share limit, sequential, first/last, super seeding, automatic management. The group labels use the rail's section style (small caps, accent), so they read as the same family.

Recommend the three groups, in that order.

G2

Which new fields

All of these are already in torrents/properties or the torrent row, so none needs a new request. Each is one row. Pick any; the sheet starts with the ones I'd add.

  • Connections "15 of 100". This is qBittorrent's first question when a torrent is slow.
  • Last seen complete. This tells you whether a stalled torrent can still finish. It's the most useful of the lot.
  • Seeding time and completed on. Both matter for ratio and seeding-time rules on private trackers.
  • Average speeds ↓ and ↑.
  • Reannounce in.
  • Piece count and size as a separate row in Information. The Pieces row in Transfer then becomes the bar in G3.
  • Private.
  • Magnet: shown shortened, and copied whole with y.
  • Popularity (qBittorrent 5): ratio per month active. It's niche, so I'd leave it out.
G3

A pieces bar

This is the most common visual in torrent clients, from µTorrent's two bars to qBittorrent's Progress and Availability. It shows at a glance whether a torrent is stuck on its last pieces, or whether the swarm is missing a region.

It would sit at the top of General, one bar 10 u tall, drawn from torrents/pieceStates, with green = have, accent = downloading, and empty = missing. For a torrent with 50 000 pieces, several pieces share each pixel. The availability bar qBittorrent draws isn't possible here: the WebUI API has per-piece states but not per-piece peer counts. The Availability row (38.20) stays as the number.

  • General only: one bar, at the top of General.
  • Every tab: under the head strip, 3 u tall, visible on all four tabs.
  • No bar.

Recommend General only. The head strip already says 48.9 %; a bar on every tab would repeat it.

G4

Per-torrent options

You can set sequential download and first/last pieces when adding, but not on a torrent you already have, and super seeding and automatic management aren't reachable at all. Deluge and Transmission give them an Options tab. qui puts them in General.

Recommend both: they show in General's Options group, where enter toggles the row under the cursor, and they're rows in the table's actions menu so they work on a selection of torrents too.

G5

Copy a value

General has no cursor today, so y can't copy a hash or a save path. You have to select the text with the mouse. Motrix and qui copy any value on a click.

Recommend General rows get the same j k cursor as the other tabs. y copies the value (the full magnet or hash, not the shortened one), a click on a value copies it too, and the footer confirms "copied hash v1".

Ideas I wouldn't build now
