The widget's settings page

The bar widget's look and clicks have nowhere to be changed: its manifest lists nine settings, but Omarchy 4.0.4's shell reads that list and draws no form for it. Q11 ("no settings view in the popup", 2026-10-02) assumed it would. Ruled 2026-10-03: the gear in the popup opens a settings page inside the widget with all of them, and the app's Settings › Appearance says where they are. This board draws that; the calls at the end settle the details before it is built.

Supersedes Q11 only. Everything else in docs/20-companion-widget-contract.md stands. Today the settings can only be set with omarchy bar set chaves.omaseed KEY VALUE --json, and without --json the value is stored as text, which the widget ignores.

Theme

The page replaces the popup's sections, in the same card. Its rows work: click one (or move with j k in the page and press space), and the bar on the right changes the way the real one would, at once. esc or the back arrow returns to the sections.

How it saves

  • The widget saves through the shell's scoped call for its own bar entry, shell.updateEntryInline("chaves.omaseed", { showSpeed: true }) (services/PluginShellApi.qml). It writes typed values to shell.json, and the bar redraws at once. No process, no file writing of our own.
  • A widget hosted by a third-party bar may not get that call. Then the page falls back to omarchy bar set chaves.omaseed KEY JSON --json, which ends in the same place.
  • The widget also starts reading text values ("true", "3") as their typed meaning, so an omarchy bar set without --json works too.
  • The app never writes these settings; it only opens the page. Tray icon stays an app setting: it is about the app's icon, not the widget.
