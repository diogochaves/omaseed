#42 says the add sheet's model keeps a file's last priority when unticked. It doesn't: a tick sets it to normal. D3 decides whether both trees should remember it.

The proposal, in short

  • One tick column in both trees, the add tree's as it is: ✓ all wanted, – mixed, · skipped. One click per file or folder. In the Files tab a click sends the priority straight away (torrents/filePrio), as x does now.
  • "All / none" becomes the column's head: both trees get a header row (the Files tab has one; the add tree gains Name · Size · Priority), and its first cell is the same tick, for every file. Click it: all ticked; click again: none. Mixed shows –. The dim words go (D1).
  • Keys: ctrl+a ticks all, then none, in the add tree. The Files tab keeps space for marking, as the table does. x becomes "skip or keep" on the marked rows or the cursor row, so ctrl+a x is all / none there (D2). Both hint lines name it.
  • Ticking a file back restores the priority it had (high stays high) rather than resetting to normal (D3).

Proposal

Folders and the head tick work like the add tree's folders today. A click on a – or · ticks everything under it. A click on a ✓ skips everything. In the Files tab a folder's tick is one torrents/filePrio with every file id under it.
With a filter on (Files tab, /), the head tick covers the files the filter shows, and its tooltip says how many (D4), as ctrl+a marks "all visible" today.
Magnets (#39 part 3). qBittorrent 5.2.3 has torrents/fetchMetadata (a magnet in, its hashes back while it looks, the file list once it has it) and torrents/parseMetadata (a .torrent in, info.files out; tried, it works). In the box, fetchMetadata didn't bring the public sampler's files back within 30 s, so the flow isn't proven yet. D5 recommends its own issue.

qBittorrent takes many in one torrents/add: several torrents file parts and several urls, one per line, sharing one set of options. Checked in the box: three .torrent files in one request answered success_count: 3.

Proposal

When more than one source arrives, the sheet becomes a batch. The source field turns into a list of torrents. Everything below it (category, tags, Save to, layout, limits, the switches) applies to all of them. Name and Files drop out: they belong to one torrent. Add N sends one request.

How a batch starts (D6): browse with several files chosen (the picker becomes multi-select, getOpenFileContent is replaced by a multi-file dialog); a paste of several lines or several links side by side (Xdg::parseAddableList already splits them; the sheet just doesn't use it); a drop of several files; ticks in In Downloads.
Hand-offs while the sheet is open (D7): a magnet clicked in the browser joins the open sheet and turns it into a batch. If you've already chosen files or renamed something there, it queues as today, so nothing you set is lost.
Request: one torrents/add with every file part and every link in urls, one per line. The toast says "Added 3" and the table's cursor goes to the first.

4 · #38

Choosing what wakes omarchy-console's rail

Since 318ea9f the widget tells the console when it's "awake" (consoleReading in plugin/Status.js), and a rail with omaseed in right.wake moves it to its running zone while it is. Today that's fixed:

something downloadsdownload speed above 0awake · running
qBittorrent unreachableor the app not answeringawake · failed
uploads, torrents in errorseeding all day; a few with missing files for monthsnever wakes it

Uploads and errors stay out on purpose: a library that seeds all the time would keep the widget in the running zone for good. What counts as "in use" differs per person, so it becomes a setting.

Rules either way: uploads wake it with no speed threshold (the rail already waits 1 s before moving a widget up and lingers 3 s before moving it down). Errors wake it as failed with consoleReason "N errored". When errors and a download both apply, D15 picks the state. Tests in tests/plugin/tst_Status.qml, one per switch and per combination. The box check uses a copy of your desk (all plugins, shell.json, console.json, console-profiles), as in session 23.
