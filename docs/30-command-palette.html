The command palette

omaseed has a key for every action, but a key you don't remember is only findable in the ? sheet. A command palette fixes that: one key opens a list of every action that makes sense right now, you type a few letters of its name, and enter runs it exactly as its key would. Each row teaches the key, so next time you can skip the palette.

Most of it is already built: the palette itself, the matcher, the table of keys and a runner. What is new is the list of commands, a rule for which rows can run now, and the key that opens it. §1 shows the app today in real screenshots; §3 onwards are mocks at base 14 in Theme roles. Use the theme switch below for the mocks.

5 · which rows, and when they can run

The list, and the rule that dims a row

Which rows appear

  • Every command that isn't a movement: the window's global commands, the torrent commands, and the focused area's own commands (D2). Torrent commands are always listed, whatever has the focus, because the selection is there whatever has the focus. The selection bar works the same way.
  • Menu-only actions too: the four option rows of the actions menu and the two limit sheets of the ⋯ menu. Each becomes a Keymap entry with an empty key and a via path (D3). Key routing and the footer hints skip entries with no key, so nothing else changes.
  • Left out: movements and gestures (j k g G h l, space v, esc, 0–8, 1–4), the actions and ⋯ menus themselves (the palette lists their rows), super+t (a desktop key), and the areas of sheets and palettes (columns, add sheet, search): the palette opens only over the window, never over another overlay.
  • One action, one row. p becomes two rows, start and stop, on the whole selection, as the selection bar's two buttons do (D5). Each dims when it would change nothing. The key p shows on whichever one p would run now.

When a row can run

Each entry says what it needs, as a plain word. The rule follows what the actions menu and torrentAction() already do: act on the selection, or on the cursor row when nothing is selected.

Order

With nothing typed: the focused area's own commands first when it isn't the table (P5), then the last five commands you ran (D7), then the rest in the ? sheet's order, then the rows that can't run. With a query: Fuzzy.score, then rows that can run before rows that can't, then recent ones first. Recent commands are kept by action id in state.json, beside the table's state.

7 · building it

How it would be built, and the demo page

Data stays plain

The omaseed site's page copies the window in hand-written JS: its actions menu is a list of strings and a switch on them. For the palette to work there too, every entry stays plain data (strings, no functions), the action id is a plain string, and the rows come from one pure function of a plain context. The site keeps a copy of the table and of that function, and its own switch on the same ids.

// Keymap.qml: two new fields on a command's entry
{ "area": "table", "key": "P", "action": "forceStart",
  "label": qsTr("force"), "title": qsTr("force start"),
  "needs": "torrents", ... }
// a menu-only action: no key, a path to it
{ "area": "table", "key": "", "via": "enter s",
  "action": "sequential", "title": qsTr("sequential download"),
  "needs": "torrents", "column": "", ... }

// one pure function, plain in and plain out
Keymap.commandRows({ area: "table", selected: 2, cursor: "Field Recordings…",
  stopped: 0, running: 2, options: { seqDl: false },
  details: "general", marked: 0, serverLost: false,
  recent: ["stop", "location", "copyMagnet"] })
// → [{ action, title, meta, detail, disabled }]
