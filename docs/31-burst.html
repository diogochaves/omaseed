Burst

qBittorrent has two sets of speed limits and a scheduler that switches between them. Everyone uses the second set as the slow one, the turtle. Someone who seeds all day on the line they also work on wants it the other way round: a daytime cap that keeps the line usable, and the full line at night, when nobody is on it. That is the same mechanism with the sets swapped. omaseed already reads, writes and toggles all of it, but it calls both directions "alt-speed", so the chip can't say which way it went or when it ends. This board names the state from the two sets, says until when, and makes the Speed page say what the schedule really does.

The screenshots in §1 are real: commit 0035a70 in an omabox (Omarchy 4.0.4, Hyprland 0.56.2, 1920×1080, theme baseline, base 14), on the box's own qBittorrent 5.2.3. Every fact in §2 was checked on the :8081 playground and the playground was put back as it was. The names, limits and times in the mocks are example data. Use the theme switch: the mocks use Theme roles only.

A window past midnight reads the days backwards

For from > to (23:00 to 07:00), qBittorrent swaps the two, starts from "on", and turns it off only when it is daytime and today is one of the picked days. So on a day that isn't picked, the alternative limits are on all day.

A qBittorrent quirk, noted for you to triage. Nothing goes to qBittorrent from here. It matters to this board twice. omaseed must reproduce the rule exactly, quirk included, to print "until" and to know a hand toggle from the schedule. From and to the same (07:00 → 07:00) is never on: the window is a single instant. The Settings line says "never" rather than leaving it to guess.

3 · the state model

Burst, turtle, or plain alt-speed, read from the two sets

For each direction, compare the alternative limit with the normal one, with 0 read as ∞. Each direction comes out faster, slower or the same.

  • burst: at least one direction faster, none slower.
  • turtle: at least one direction slower, none faster.
  • alt-speed, today's word: faster one way and slower the other, or the same both ways.
  • off: alternative limits not in force. The chip is its glyph alone, as today, whatever the sets are.

The word only describes the set. It doesn't change what A does or what qBittorrent stores, so nobody has to choose a mode. Someone who uses the set as a turtle sees "turtle", in the same yellow, with the same limits, in the same place. Nothing they have today goes away.

The bar widget

The widget reads the status file and never asks qBittorrent itself, so the app works the word out and writes it: alt.kind ("burst" · "turtle" · "alt"), alt.until ("07:00", "Mon 07:00" or "") and alt.byHand. These are additions to STATUS.md: an older widget ignores them and keeps today's yellow.

5 · settings › qbittorrent › speed

Say which way the set goes, what the schedule does, and where to set burst

The rows stay qBittorrent's (the same keys, the same order). Three things are new, outlined in the mocks. A line under the four limits names the set. A preset fills the schedule. A plain summary under Days says what the schedule really does, computed with qBittorrent's rule. Row titles follow the word: "Schedule burst" for burst, "Schedule turtle" for turtle, today's "Schedule alt-speed" otherwise.

Why "nights" and not "nights and weekends" (D8). qBittorrent has one window. "23:00 to 07:00, weekdays" happens to give nights and all weekend, through the backwards reading in §2. A preset built on that would look wrong in the Days pick ("weekdays"), and it would stop doing what it says if qBittorrent fixed the rule. "nights" is plain and lasting. Someone who wants weekends can pick "weekdays", and P2's summary will tell them it does nights and weekends.
The guidance line is a claim, so it waits for a measurement (§7). µTP (LEDBAT) yields to other traffic. TCP peers don't, and many peers use TCP. omaseed doesn't measure the line. You type the number.
6 · per server

Each qBittorrent keeps its own sets and schedule

  • The word, the end and the "by hand" guess are worked out for the server omaseed is on: the default one, the one the hero names. Switching servers works them out again from that server's preferences.
  • The widget, the tray and the status file show the same server, as they do for speeds.
  • Settings › Speed edits the server named in its header, as today.
  • One server can be burst while another is turtle. Nothing is shared or copied between them.
  • Times are the server's clock, and the API doesn't give its time zone. For a server in another zone the time printed is still right ("07:00" is the schedule's 07:00). Only the day and the "by hand" guess can be wrong: omaseed works them out with this computer's clock. No server line or setting for this. If it turns out to matter, a server could get a time-zone field later.
  • Fresh preferences: today they're read on connect. They should also be re-read when use_alt_speed_limits flips, which happens a few times a day, so a set or schedule changed in qBittorrent's Web UI shows the next time it switches (D13).
7 · building it

How it would be built, and what to check first

core

  • SpeedSets::kind(normal, alt): burst, turtle, mixed, same, from four limits, 0 as ∞. Pure.
  • AltSchedule from the preferences: onAt(dateTime) with qBittorrent's rule, swap and days included; nextChange(from, state), the first time the schedule would move the state the other way (a scan by the minute over 8 days); summary() for the Settings line.
  • QtTests: every row in §3's table, T1–T7 from §2 as fixed times, every backwards-days row, from = to, midnight, a Sunday-to-Monday weekend end, and a daylight-saving change.

app and views

  • App: altKind, altUntil, altByHand. Re-read preferences when alt flips.
  • Hero chip, the tooltip, the measuring copies; Glyphs.burst; the footer note after A; the ? line; ⋯ and the limits sheet; QbtSettingsSections: titles, the set line, the preset, the summary, the guidance line; Tray: menu label and a burst mark.
  • Plugin: STATUS.md alt.kind/until/byHand, Status.js altLine and the mark's square, the popup button's tooltip, the bar tooltip's "M:". Bump the widget's version.
  • A DECISIONS.md entry for the model, and a spec line in REVIEW-v0.1.0.md: this changes the v2 hero chip (Fig. 1).

checks

  • A walk in an omabox on a box-owned qBittorrent (app-box.sh up --qbt --plugin plugin): set a burst pair, a schedule around now, then A both ways; shots of the chip, footer, tooltip, Settings, mark and popup; the schedule's flip within 30 s.
  • The 22-theme sweep for the green chip and the needle on light themes.
  • Before the guidance line ships (not run for this board): on the :8081 playground in an omabox, cap the box's link (or the playground's own global limit as a stand-in), set burst at 90 % of that cap, run a parallel transfer and a ping, and record the latency and the parallel transfer's speed, once with µTP only and once with TCP peers. If the line doesn't stay usable, the copy changes (a lower percentage, or no µTP clause). Never :8080.
