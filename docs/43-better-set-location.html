A better set location

Board 42 built a move for a whole folder: checks before anything is sent, a job that runs in waves, a band while it runs, one summary at the end. Set location, the move for one torrent or a selection, still has none of that. This board makes every move a job. A folder and a selection become two ways to start the same thing, on the same machinery.

§1 has real screenshots of today and one new finding. §2 onwards are mocks at base 14 in Theme roles; use the theme switch for them. The examples are made up: a server "home", folders under /srv/media and /mnt/fast. The calls are L1–L12 in §11; at the ruling they become one C entry in DECISIONS. Board 42's M calls are cited as M1–M20.

2 · one sheet

Board 42's checks, quiet when there is nothing to say

Set location opens MoveSheet in a selection mode instead of LocationSheet. It is the same sheet as board 42's S1, with what a selection doesn't have taken out: no loose files (a selection is not a folder), no path rows unless the torrents come from several save paths (§4). The checks are M5–M8's, read again whenever the field changes. A line shows only when it says something, so moving one torrent within a drive stays as short as today.

3 · where to

Places to pick, not only a path to type

The field opens a list under it on ↓ or as you type: the library's folders (board 42's tree, so the rail and the sheet agree), the categories' own folders, and where you moved things lately. Typing filters all three. Browse (ctrl+o, #41) stays at the end for anywhere else.

4 · several save paths

Into one folder, or keep their places

A choice shown only when the torrents come from more than one save path (Shot 3). "Into one folder" is today's behaviour, now said out loud. "Keep their places" is board 42's rule applied to a selection: the common folder of their save paths is the root, and each torrent keeps its path below it.

5 · every move a job

A band only when it is slow, a summary only when it was

Every move goes through MoveJob: smallest first, the first alone (M6, M12), 3 with qBittorrent at a time (M11), saved and resumed after a restart (M13), the log read for its whole life (M15). What changes for a selection is how much of it you see. A move that lands within a few seconds (one torrent, a rename on the same drive, small files) shows no band: the rows change, and the footer's note says it landed. The band appears only once a move has run longer than that.

6 · one big torrent

Real progress, measured at the destination

qBittorrent says nothing between "moving" and "moved", so a band for one 40 GB torrent could only show a spinner and a clock. When the destination maps to this machine (the path map, as for M5), omaseed can read how many bytes of that torrent's files are already at the target, every 2 s, and show real progress. MoveJob already has the hook for this (setGrowthProbe, used today only to tell "stuck" from "slow", M14); it is not wired in the app yet.

7 · the end

The summary, and "move back"

A move whose band showed ends as board 42's does: the green band until closed, failures one click away (M16). New for every job, folder or selection: move back. The job's record already has each torrent's old save path, so moving back is a move like any other: it opens the sheet with each torrent going to its own old place, the checks run, nothing is sent until you press it.

8 · while a folder moves

One job per server; the next one waits its turn

M18 holds for every move: one job at a time per server, because qBittorrent moves one torrent at a time anyway. A set location while board 42's folder move runs is checked at once and queued behind it.

9 · what goes, what stays

One move, so one set of rules

Goes

  • C2 D2's 30 s watch, for moves. Every move is a job and its log is read for its life (M15). D2 stays as it is for renames and deletes with files.
  • LocationSheet. MoveSheet takes its place, in a selection mode. Its parts live on inside it (below).
  • "Set location" as the action's name, if L2 is ruled as recommended: "Move…" in the menus, the palette and the sheet's title. : still finds "set location".

Stays

  • m for a move of the selection, shift+m for the picked folder (M1).
  • The shared-data guard (#28, #35, board 26): its yellow box, "move both" / "move only this one", and their words, unchanged, as one more line group in the sheet.
  • Browse and ctrl+o (#41), and the browsed-path line under the field.
  • docs/32 F1: the error block's "set location" opens the sheet prefilled with the destination that failed.
  • C2 D1's yellow block in General for a failed move, and its actions.
  • The words for a refused move (M19).

10 · how it's built

Board 42's pieces, opened up to a selection

MovePlan
Input today takes the whole library, a root and a new path. It gains a target rule: keep places (root and new path, today's), one folder (every torrent to one path), and each its own (a hash → path map, for "move back"); and a set of hashes for a selection. The checks (room, writability, clashes, auto-management, shared data, already there) stay as they are. New QtTest rows for each rule.
MoveController
About 1,900 lines that assume a folder. Split into the sheet's side (a plan for a folder or for a selection, places list, recent destinations) and the job's side (start, pause, band, summary, move back, the queue). App::setLocation starts a selection job instead of sending one request; ProblemLog::watchMove goes, watchRename and watchDelete stay (D2).
MoveJob
A "shown" moment for the band's delay (L6), a quiet success note for a job that never showed, and setGrowthProbe wired to a probe that reads the target's file sizes through the path map (L10), feeding bytes moved and time left as well as stuck.
views
MoveSheet in selection mode takes LocationSheet's SharedDataLine, SharedChoice and BrowsedPathLine; a places list under the Field (a Kit popup list with its own tst_*.qml); the structure choice; "move back…" on the summary band. LocationSheet.qml is removed.
tests
tst_moveplan (the three rules, a selection), tst_movecontroller (a quick job never shows; a slow one does; move back; a queued selection), tst_Actions.qml's set location cases rewritten for MoveSheet. actions-walk's set location steps now expect the job's footer note and, for the 2 GiB move onto tmpfs, the band; it gains the clash of Shots 4–5, left out. move-walk gains a selection across two save paths with "keep their places", and a "move back".
engines
Nothing engine-specific: MoveJob's types are neutral and the qBittorrent side stays in QbtMoveFeed. Transmission's torrent-set-location with move: true fits the same feed when E4 comes, so set location gets the job on every engine at once.
