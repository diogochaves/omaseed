Torrents in the Omarchy menu

#211 asked for a switch to take omaseed's Torrents row off Omarchy's menu without editing a file. Looking at the row as a whole showed a bigger problem: a row on the menu's first page that only opens the app doesn't fit how Omarchy builds its menu. This board proposes Trigger › Torrents, a submenu of things you do to omaseed from the keyboard, with one switch in Settings › Appearance that adds it and takes it away. The menu pictures were taken in an omabox against the playground, with the rows written into the box's menu file. The launch option, Pause / Resume and the notices don't exist yet: those are drawn.

1 · today · v0.6.0, in an omabox

A row you add by hand, last on the first page, that opens omaseed

  • The row is one line, "torrents": {…,"label":"Torrents","action":"uwsm-app -- omaseed"}, shipped in /usr/share/omaseed/omarchy-menu.jsonc. The README says to copy it into ~/.config/omarchy/extensions/omarchy-menu.jsonc; scripts/dev/install-omarchy-extras.sh --menu appends it. It came from the charter's list of integrations and was never on a board.
  • It only starts omaseed, or raises its window when it runs (one instance per session). Apps › omaseed and the launcher already do that.
  • It can't be placed. The menu lists its own rows first, in its file's order, then the user file's rows in that file's order; there is no position field. An added row on the first page always comes last, after System.
  • Taking it away means editing the file (#211). Omarchy gives every user that file, and the menu reads it again when it changes: a row added or deleted shows on the next open, without a restart.
2 · how Omarchy's menu is built

Sections first, apps' actions inside them

Omarchy has no written guide for added rows; these are read from its own menu file.

  • The first page has sections, never apps: Apps, Learn, Appearance, Trigger, Setup, Install, Remove, Update, About, System.
  • Trigger holds what you do now: Toggle, Emoji, Clipboard History, Reminder, Capture, Transcode, Share, Hardware, Speed Test. An app's actions live there by what they do: Share › Receive starts LocalSend.
  • On and off are two rows, named by what they do, each with a when so only one shows: Stay Awake / Allow Sleep, Nightlight On / Nightlight Off. The ✓ (checked) marks one pick among several (Opaque, Glassy or Clear bar).
  • Every row can be typed for from the first page, at any depth, and an aliases entry is a route for omarchy menu summon NAME, which a key can be bound to.
  • Short Title Case labels. Its longest is Clipboard History; the menu cuts what doesn't fit (§3).
3 · M1 · what omaseed puts in the menu

Three answers

M1 aTrigger › Torrents, things to do to omaseedrecommended

A submenu at the end of Trigger, beside Capture and Share. From anywhere, with the keyboard: open omaseed, add or search a torrent, pick the speeds, pause and resume everything, switch servers, open its settings. The rows that open the window always show; the rows that change something show while omaseed runs. Reached by typing torr on the first page, or straight from a key bound to omarchy menu summon torrents.

M1 bThe first-page row, with a switch

Today's row, which a switch in Appearance adds and removes (or hides with a flag file and a when, as #211 proposed). It fixes #211's complaint but keeps a row that only opens the app, last on a page of sections, that can't be moved.

M1 cRetire the row

omaseed stops shipping it; Apps and the launcher remain the way in. The changelog tells anyone who copied it to delete the line. The least to build and keep, and the keyboard gets nothing.

Recommended: a. It is the menu's own pattern: an app's actions inside the section for what you do, toggles as pairs, picks with a ✓, found by typing, summoned by a key. It gives the row a reason to exist, pausing everything or picking turtle before a call without bringing up the window, and it answers #211 too, since the same switch takes it away. The tray, the bar widget's ⋯ and the window's mark already share one menu for the pointer; this is the keyboard's way to the same actions.

4 · M2 to M5 · the submenu

Its rows, and how each reaches omaseed

The rule. A row that opens the window runs omaseed with a launch option and always shows: it starts omaseed when it isn't running. A row that changes something calls omaseed's bus and shows while omaseed runs: a pause or a speed change shouldn't wait on a cold start. Speeds › and Pause / Resume also hide while the server doesn't answer, where the tray dims them today (their when also reads server.reachable in the status file); Servers › stays, since moving off a server that doesn't answer is when you want it. Ruled 2026-11-05.

M3How a row reaches omaseedrecommended a

a: the rule. The window's rows run omaseed itself with a launch option (M5). The other rows call busctl --user call on the bus omaseed already has (io.github.diogochaves.omaseed.Status), the way the bar widget acts. Whether omaseed runs is busctl --user status on its name; the pairs and the ✓ read its status file with jq, which Omarchy ships. Both halves were run from the menu: on the first try, Alt Speeds On changed the playground's limits within a second; on this one, a server picked in Servers › moved the app (§5). b: everything through a new omaseed --invoke ID, one kind of line, but each state row starts a second omaseed only to hand the call over.

M4While omaseed isn't runningrecommended a

a: the window's rows show, the others don't (the right picture in §3). b: every row shows, and a state row starts omaseed first, then acts: a pause or a speed change waits on a cold start and a first sync. c: only Open omaseed, as the first try had it.

The option adds two actions, add and search; settings is there already.

  • add: the blank add sheet, as the tray's add torrent… does today (the window raised, then the sheet, AppBarMenu.cpp), where board 54 rules it opens. This board doesn't draw it.
  • search: the window on the search view (board 48).
  • settings: the window on Settings.

a: one option, omaseed --open add|search|settings, its values the names ActivateAction uses; a new face is a new value, not a new flag. b: one flag each, --add, --search, --settings, as --quit is.

5 · M6 to M11 · what the rows do

Speeds, pause and resume, servers

M6Speeds ›recommended a

omaseed has two presets for qBittorrent's one set of alternative limits (DECISIONS C32 D8 a, amending C4 D1–D2). Turtle is that set at rest: the server's own alternative limits, the ones its schedule turns on. Burst is omaseed's: ↓ no limit, ↑ 2.00 MB/s, for 30 or 60 minutes or until stopped (60 by default). Picking burst saves the turtle, writes burst's limits over the set and turns the alternative limits on; when it ends, the turtle is written back. In the window the chip opens a picker (off · turtle · burst); A and the shared menu's one row flip the last pick.

a: Speeds › with three rows and Omarchy's ✓ on the one in force. The ✓ is what Omarchy uses for one pick among several (§2). Burst runs for the length Settings › qBittorrent › Speed sets. b: one pair named for the last pick, Turtle On / Turtle Off or Burst On / Burst Off, flipping it as A does, written again when the last pick changes. c: the first try's static pair, Alt Speeds On / Alt Speeds Off, on SetAltSpeed: it also flips the last pick, and the menu can't say which.

M7The speeds' wordsrecommended a

a: Normal · Turtle · Burst. b: Off · Turtle · Burst, the chip's words; alone in a Speeds menu, Off reads as no speed. c: Full Speed · Turtle · Burst, which lies when the normal limits cap something.

M8The pick on the busrecommended a

The bus has ToggleAltSpeed, SetAltSpeed(b) and Invoke alt-speed, all of them on and off; none picks a preset. a: a new method, PickAltSpeed(s off|turtle|burst) → b, beside SetAltSpeed, and a status-file field alt.pick (AltPresets.current(): off, turtle or burst) for the ✓. alt.kind can't serve: it compares the limits in force with the normal ones, which is not the pick. b: Invoke ids alt:off, alt:turtle, alt:burst, with the same field. No new method, but Invoke's ids are the shared menu's rows, and these aren't among them.

One notice for each pick that doesn't come from the window: this menu, the tray, the bar widget. In the window the chip already shows it. It says what was picked, its limits and for how long, in board 31's words (DECISIONS C4).

When the turtle's limits are still qBittorrent's untouched defaults (10240 B/s each way, read from an untouched 5.3.0 profile), the notice says so and points to Settings › qBittorrent › Speed. Someone who never set a turtle learns why it crawls.

a: a notice for every pick from outside the window. b: only for this menu's rows (PickAltSpeed). c: none.

M10Pause Torrents / Resume Torrentsrecommended a

Today Stop All and Start All send qBittorrent hashes=all on the current server (App.cpp, stopAll and startAll). So Start All also starts the torrents you keep stopped on purpose. Omarchy names a pair for what it does (Stay Awake / Allow Sleep), and shows one at a time.

drawn · the pair
Pause Torrents→every torrent that isn't stopped is stopped→their hashes kept for this server, across restarts→Resume Torrents shows
Resume Torrents→those torrents started, the ones still there and still stopped→the list forgotten→Pause Torrents shows
  • A torrent you start by hand meanwhile is left as it is and leaves the list; one deleted leaves it too.
  • The pause is kept per server, in state.json, so each server shows its own pair after a switch.
  • The status file gets paused.count (0 with no pause held) for the menu's when; plugin/STATUS.md adds it within v2. Invoke takes pause and resume in place of stop-all and start-all.

The tray, the bar widget's ⋯ and the window's mark share one menu, so the pair changes it too. That amends DECISIONS C13 (D24 a, the rows stop all and start all) and C20's line on their order; board 33 §11 stays as ruled. a: Pause / Resume everywhere: the shared menu's stop all and start all become pause torrents and resume torrents, resume shown only while a pause is held. b: Pause / Resume in Omarchy's menu only; the shared menu keeps stop all and start all, so one desktop has two ways to stop everything. c: keep Stop All / Start All as today, in both.

M11Servers ›recommended a

One row per server, Omarchy's ✓ on the current one, shown with two servers or more while omaseed runs. A row calls the bus's SwitchServer(s id), as the shared menu's servers block does, and the ✓ is a jq test on the status file's servers[].current.

The first try said an added file can't list servers. That holds for a list the menu fills when it opens, which only Omarchy's own providers do (a fixed list in its shell). But omaseed owns its block, so it writes one row per server, and writes the block again when the list changes: a server added, removed or renamed, which is rare.

a: Servers › as above. b: no servers; the tray, the widget and the window's mark have them.

What else changes

  • /usr/share/omaseed/omarchy-menu.jsonc holds the block instead of the row, with no Servers rows (a hand copy can't know your servers), so a hand copy still works and the switch reads it as on.
  • install-omarchy-extras.sh --menu writes the block, --uninstall removes it.
  • The README's Omarchy section points at the switch; the changelog says the first-page row moved to Trigger › Torrents.
  • New: the launch option (M5); PickAltSpeed and alt.pick (M8); pause, resume and paused.count (M10), written into plugin/STATUS.md.
  • Unchanged: the .desktop file and Apps › omaseed.
7 · building a

Five pieces, each a PR of its own

For whoever builds it: #211's author if they want to, otherwise the maintainer. The first piece suits a first outside contributor: it has no UI and stands alone.

  1. The block and the file rule. A class in src/core/ reads the menu's file into one of M13's states and adds, rewrites or removes the block. Pure Qt, no QML. A QtTest covers every row of M13's table, the cases tests/dev/test_install_extras.sh has, and that every other byte survives an on and an off. install-omarchy-extras.sh moves to the block.
  2. The launch option and the menu's rows. --open in main.cpp, add and search beside settings in ActivateAction; the block's text, built from one template in data/omarchy-menu.jsonc plus a Servers row per server.
  3. Pause / Resume. The held list per server in src/core/ with a QtTest; Invoke pause and resume; the shared menu's two rows (BarMenu); paused.count in the status file; the amendment in docs/DECISIONS.md.
  4. Speeds on the bus. PickAltSpeed through AltPresets, alt.pick, and the notice with the untouched-defaults line (Notifier).
  5. The switch. An App property beside inTheBar that watches the file; the row in SettingsModal.qml after Widget; a QML test in both skins (ctest -L skin-console); a step in scripts/dev/settings-walk.sh that flips it in a box, opens omarchy menu summon torrents, picks Turtle and checks the server; the README and changelog lines; the ruling in docs/DECISIONS.md.
