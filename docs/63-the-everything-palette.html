The everything palette

Today omaseed has one palette to run a command, another to jump to a torrent and a third to switch server, and none that finds a setting. This board proposes one palette over all of them. Each of today's keys opens that same palette with a filter already on: ctrl+k is the everything palette showing only torrents.

The name is Ryan Fleury's, from the RAD Debugger: one palette drawn from the app's own list of what exists, so a thing added once shows up everywhere. omaseed already works that way for keys (the Keymap feeds the routing, the ? sheet and the command palette). Every figure here is a mock at base 14 in Theme roles, built on the palette as it is today; board 30 has real screenshots of today's palettes. Torrent and server names are invented. Use the theme switch for the mocks.

2 · the idea

One palette, four kinds, and a filter

Kinds

A row is one of four kinds: a command (run it), a setting (change it), a server (switch to it) or a torrent (go to it). Each kind keeps the row shape, the ranking and the enter it has today.

The filter

The palette opens on every kind, or narrowed to one. Narrowed to torrents it is today's jump palette, row for row. Narrowed to servers it is today's server palette. Clearing the filter widens it again without closing.

What does not change

Every key keeps its habit. / still filters the table and ctrl+f still searches the plugins, because those change what the window shows. The four pickers stay separate palettes.

3 · Z1 Z2 Z3 · keeping the kinds apart

de typed into the whole palette, three ways

A library holds thousands of torrents and the app has about fifty commands. If they share one ranked list, torrent names push the commands out. The three mocks show the same matches for de, with two torrents selected in the table.

Z2 · The order of the sections

Fixed: commands, settings, servers, torrents. The short kinds come first, because a word typed here is more often something to do than somewhere to go, and ctrl+k already goes straight to torrents. The alternative moves the section with the best match to the top, which is cleverer but makes the list jump as you type.

Z3 · How many rows a section shows

Up to four, then "N more", when more than one kind matches. When only one kind matches there is nothing to keep apart, so the heading and the cap go and the list is that kind's whole list. At 560 px wide and about 52 px a row, four kinds of four rows fit in one scroll of the palette.

Inside a section

Each kind ranks as it does today. Commands: Fuzzy.score, then rows that can run, then recent ones (C1 D4, D7). Torrents: App.jumpMatches(), over name, hash and tracker. Servers: their list order. Settings match their title and their pane's name.

Z7 a · The control lives in the row recommended

S1, S2 and S3 as drawn. The palette becomes the fast way to flip a switch without learning the modal. It can be built in two steps: every setting as S3 first, then switches and choices.

Z7 b · A setting row only goes to its pane

Every setting behaves like S3: found here, changed there. It is far less to build and there is one place where a setting changes, but each change costs two more steps.

Which settings are rows

omaseed's own panes, and the settings of the server on show, as its engine offers them (C14 E4 hides the rest). Another server's settings are not listed; its pane already says "switch to … to change these". The Backup pane's actions (export, import, restore) are commands, not settings.

7 · Z9 Z10 · scope

Which palettes fold in, and which kinds come first

Z9 · The pickers stay

Category, tags, sort and columns answer a question an action asked ("which category for these 4?"). They tick, reorder and create on a miss; none of that is "find a thing". Their commands ("set category…", "columns…") are already rows of the command kind, and that is how the everything palette reaches them.

Z10 · Kinds in the first build

Commands, settings, servers, torrents. Two more could come later as their own kinds: the rail's places (a category, a tag, a tracker: enter filters the table to it) and the move history (C18: enter offers "move back"). Each adds a section, so each should prove it is asked for first.

Torrents of which server

The server on show, as the jump palette today. Finding a torrent across every saved server belongs with the multi-server view (parked in #7), not here.
