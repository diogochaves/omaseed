The add sheet: the files, and the room

Board 59 gave the add sheet four new lines. Two things it doesn't give are what Diogo found missing. First, the file list: in the add sheet it sorts only by name, can't be filtered, can't fold or unfold everything, and lives in a 600 px column under a form. A pack of 28 files ends up as a long, narrow scroll. Second, the room: the free line checks only the folder a torrent ends in. When the server first downloads into a temporary folder on another drive, the sheet says "fits" while that other drive fills up. This board proposes a two-column add window whose right side is the whole file list, with the details tab's tools and one of its own. It also proposes a free line in two stages: where the torrent downloads first, and where it moves when done.

What a missed temp folder costs, measured in #117 on qBittorrent 5.2.4: when the folder it moves to is full at the finish, qBittorrent logs a move failure that names the source file. It leaves the partial files in the destination, which is now 100 % full, and keeps the torrent stalledUP at progress 1, seeding from the temp folder. It shows no error, and a recheck changes nothing. Today D13's red still in the incomplete folder problem catches it, but only after the fact. The add sheet is the one place it can be seen before anything is written.

3 · I1, I2, I14, I15 · the window

Two columns, whatever you add

I1The layout recommended a

a: two columns for every add, whenever the screen holds them, so the window looks the same whatever you open. The form keeps today's rows and order on the left (about 440 px at base 14). The right side is the torrent: its files at the window's full height, then About this torrent (I15). The window grows to about 1120 px. A single file gets a one-row Files list (new: today and board 59 show none) with the file's own name, kind and size, which often differ from the torrent's name, and a rename. It has no tick, because skipping the only file adds nothing, and no toolbar. Its right side is mostly the About block, which is what it has to say. A magnet on its way holds board 59's checklist (A10) there until the list arrives. Then the tree takes its place and nothing on the left moves. b: one column as today, but wider (900 px) with a taller tree. Simpler, but the tree is still under the form and every row you fill pushes it down. c: files as a second step, "next: files". That's two screens for every add, including the ones where you don't care.

I2A screen too narrow for it recommended a

a: when the monitor's work area can't hold the two columns (under about 1200 px of logical width, a portrait screen, or scale 2 on a 1080p screen), the window keeps one column and the file pane goes under the form, with its toolbar. Pick narrow in §2's switches to see it. b: always two columns, with the window scrolling sideways.

The add window is its own window since board 54 (C35), a Hyprland float, so a wider one is a size, not a new frame. Board 46's sheet frame (C24 H7) still holds: the head, the hairlines, the foot's three buttons. Only the body splits.

I14Who picks one or two columns recommended a

a: a setting, Appearance › Add window: two columns · one column, two columns by default. The screen still has the last word (I2): two columns on a screen that can't hold them fall back to one. It's a taste you set once, next to Skin and the display, and the add window carries no extra control. b: a button in the window's head (⊟ ⊞, and a key), remembered for the next add. You find it where you use it, but the window resizes under your cursor, and it's one more control on a sheet you see on every add. c: both: the setting, and the button flips it for this window only. d: none: the screen decides. Pick layout in §2's switches to see both.

I15About this torrent recommended a

omaseed already parses a .torrent's own facts (core/TorrentFile), and the sheet shows none of them. a: a short block under the files: trackers (count and hosts), private (and what that means: no DHT, no peer exchange), created (date and program), comment, pieces (count × size), hash (v1, v2 or hybrid; the last bears on Transmission, #257). A magnet has only its link's trackers and hash until the list arrives. It is read-only: board 25's tracker merge stays where it is. b: only for a single file, where the right side is otherwise empty. c: none.

4 · I3 to I7 · the file pane

One file list, everywhere a torrent's files are shown

I3One component, one model recommended a

a: the add sheet and the details Files tab show the same file pane: the same toolbar, sort, filter, fold and keys. The add sheet's abilities (tick before the add, priority, rename, skip files of at least N) move into the shared model, and the details tab's (sort, filter, hide skipped) come with it. A key learned in one works in the other. b: copy the details tab's tools into AddFilesTree. That's faster to build, and then there are two of everything to keep in step.

I4The toolbar recommended a

a: one row above the list: filter (a field, / to focus), sort ▾ (name, size, kind, with "folders first" ticked by default in the tree), tree · flat, fold all and unfold all (one button that reads by state), and hide skipped. The column headers sort too, as in details. b: only sort ▾ and fold all. c: every tool behind one ⋯ menu.

I5The kinds line becomes chips recommended a

Board 59's A1 says 9 videos, 12.6 GB · 16 subtitles · 3 extras in words. Here each kind is a chip with two parts. The word shows only that kind, and a second press shows everything again. The box ticks or skips the whole kind in one press. So "skip every subtitle" or "only the videos" is one press, where qBittorrent needs a tick per file or a sort and a shift-click. a: both parts. b: the word filters, and there's no box. c: words only, as 59 drew them.

A chip's box follows C28: it never moves on its own. 59's program check (A4) is the chip in yellow, and its "skip it" is that chip's box.

I6A flat view recommended a

a: tree · flat. Flat lists every file once with its folder dim after the name, and sorts across the whole torrent, so "size" puts the biggest files in the pack at the top wherever they live. That's how you find the one 4 GB extra or the 200 small images. Ticks, priorities and renames work the same in both views. The view you pick is kept per window (add and details each keep their own). b: tree only, with size sorting inside each folder.

I7The head of the pane recommended a

a: the kinds chips on the left, today's count on the right (26 of 28 files · 12.7 GB), and while a filter is on, showing 16 of 28 with × show all. C28's extras line stays under the list. b: the count moves to the foot beside add.

5 · I8 to I13 · the room

Where it downloads, then where it lands

When the server has a temp folder (qBittorrent's Keep incomplete torrents in, Transmission's incomplete folder, Deluge's download folder with move completed), a torrent needs room twice. While it downloads, it needs room on the temp folder's drive, and that drive also holds every other download in progress. When it finishes, it needs room on the save path's drive. On the same drive the move is a rename and costs nothing. On another drive it is a copy, and if the copy finds the drive full, it leaves #117's half-move.

I8The free line, in two stages recommended a

a: two lines under Save to, each with its own meter and colour: downloads first to FOLDER · needs X · Y free on DRIVE and then moves to SAVE PATH · needs X · Z free on DRIVE. Each line goes yellow or red on its own, so a small temp drive warns even when the save path has terabytes free. On one drive the second line is dim: then moved on the same drive: a rename, no second room. b: one line that names only the tighter of the two drives. c: today's line (the save path only).

I9The temp folder, per torrent recommended a

a: the first line starts with a switch, on by default, reading the server's own setting. Turned off, this torrent downloads straight to Save to, and the two lines become today's one. When the temp drive is red, the line offers that as a link: download straight to Save to. The server's setting never changes. Where it can be done per torrent:

I10Room promised to downloads in progress recommended a

"Free" is what the drive has now. Torrents still downloading there will write more, and every download goes through a temp folder. omaseed knows each torrent's amount_left and where it is writing (its download path, else its save path). a: when other downloads write to the same drive, the line says so, and the colour uses free minus what's coming: 48 GB free · 21 GB of it still coming for 2 downloads. It counts downloading and queued torrents, not stopped ones. When the server pre-allocates (preallocate_all), their room is already taken and nothing is added. "The same drive" is known only where omaseed sees the folders (its own disks, or a path map); otherwise it says nothing. b: said, but the colour uses free only. c: left out.

I11When the save path's drive won't hold it recommended a

a: the second line goes red with #117's fact in one dim line: When it finishes, the move to /srv/media won't fit: qBittorrent leaves part of it there and keeps it in the temp folder. The add still works (board 25's D7). b: red, with no reason under it.

I12A category with its own temp folder recommended a

Since qBittorrent 4.4 a category can carry its own incomplete folder, or none. a: picking the category moves the first line to the category's folder, as a pick already moves Save to. A save path you typed keeps today's rule. To confirm on the playground how torrents/categories reports it (download_path: a path, false, or the default). b: the server's folder only.

I13The same in the move sheet recommended b

a: board 43's Set location gets the two stages too, for a torrent still downloading (it moves only when done, #98). b: not here. A later issue, once the add sheet's lines are in use.
