The guide as a skill

Today omaseed's guide for agents reaches an agent two ways: as AGENTS.md in ~/.config/omaseed/, read for free by an agent started there, and as omaseed --skill, which an agent runs only if something tells it to. An agent asked "why didn't my download finish?" in any other folder has neither. #227's trial showed the guide itself works; what it lacked was a way to be found, and a map that keeps an agent out of the 18k-token schema. This board proposes the way omabox does it: one short skill, SKILL.md with the trigger words in its description and the details in ref/ pages, shipped in the package and linked into the agents' skill folders by a command the person runs. One source makes the skill, AGENTS.md and --skill, so they can't drift.

1 · today, v0.15.1, and what the trial said

A guide that works, where an agent rarely is

  • One text, two parts. library.md (the four reads, their JSON, the exit codes) and skins.md (the loop, the rules, the tokens, sharing, the files), compiled into the binary. --skill prints both; every primary start writes them as AGENTS.md, with a CLAUDE.md that says @AGENTS.md and skin.schema.json beside them (C37 U4, C45 V19).
  • The trial (#227) gave a fresh agent, started in ~/.config/omaseed/, two plain requests. "Make omaseed warmer, and rounder": done and correct in 17 turns, but it read the whole schema (~18k tokens against ~1.8k for the guide). "Why didn't this finish?": right first time in a fresh session (status, moves, errors in one call); in a session already about skins it read "this" as its own work and never ran errors.
  • v0.15.1 took the trial's text fixes. "didn't finish, stuck, slow, missing: errors first, then moves", needsYou pointing at errors, the wish-to-token map, "grep the schema, don't read it whole", lifted rewritten, the loop cloning the drawn skin. They are in the guide now; this board moves them, it doesn't write them again.
  • What the trial couldn't test is the case that matters most: an agent started in a project folder, or in ~, asked about a download. It has no AGENTS.md and no reason to run --skill. The help page's last line helps only once the agent already runs omaseed.
  • Never used in the trial: the exit-code table, sharing, the omabox check. They belong in pages read on demand, not in what every session loads.
Board 55 left "a skill installed into Omarchy's skills folder" out, because that folder is Omarchy's. That still holds: this board never writes under Omarchy's folder. It links into each agent's own skill folder (~/.claude/skills, ~/.agents/skills…), where Omarchy, omabox and a person's own skills already sit side by side.
2 · the model

How omabox ships its skill

  • One short SKILL.md (81 lines). Its frontmatter: name, a description that says when to load it and lists trigger words, and allowed-tools naming the commands that only read. Agents load the description always and the body only when it matches.
  • "ref: FILE" pages in ref/ beside it, read only when the task needs one.
  • omabox setup links the skill folder (a link, so an upgrade updates it) wherever Omarchy puts its own skills: ~/.agents/skills and ~/.claude/skills always; Codex's, pi's and Hermes' folders when those agents are there. setup --remove unlinks only links that point at its own folder. A second skill is opt-in.
  • Omarchy's own skills (omarchy, omarchy-app…) live in its package and are linked by its migrations into the same folders, plus Gemini's and every Hermes profile's. A skill of the person's own by that name is left where it is.
3 · AS1 to AS4 · the skill

A map that loads, pages that wait

AS1One skill or tworecommended a

  • aOne skill, omaseed: SKILL.md and three pages, ref/library.md, ref/skins.md, ref/files.md. The tokens stay in skin.schema.json, which the skill names and never copies. One description, one link per folder, one name the person sees in their agent's list.
  • bTwo skills, omaseed (the library) and omaseed-skins. Each description is sharper, but two links per folder, and a request like "it's slow, and make it calmer" needs both loaded.
  • cOne SKILL.md holding the whole guide, no pages. The simplest; every match loads ~2.5k tokens, most of it unused.

AS2What SKILL.md holdsrecommended a

  • aThe map, whole enough to answer the trial's two requests alone: the never list; the four reads and "didn't finish, stuck, slow or missing: errors first, then moves; needsYou above 0: errors"; the skin loop (list, check, clone the drawn skin, edit, check both pictures, use, the way back); the wish-to-token map with "grep skin.schema.json for one token, never read it whole"; and a "ref:" line where each page earns its read. Under 70 lines.
  • bAn index only: the never list and one line per page. Loads the least; every real request then reads a page, and the trial says the loop and the map are what gets used.

AS3The description's trigger wordsrecommended a

  • aTwo plain sentences and a trigger list (the mock above): the person's own words for the trial's two requests ("didn't finish", stuck, slow, warmer, rounder), the engines' names, and omaseed itself. "Theme" and "look" only as omaseed's: "change my theme" is the desktop's, and belongs to Omarchy's skill.
  • bOnly omaseed and torrent. It never takes a request from another skill, and it misses "why didn't my download finish?", the question the skill exists for.

AS4allowed-toolsrecommended a

  • aThe six that only read: omaseed status, errors, log, moves, check (it writes only its pictures under ~/.cache/omaseed/check/) and skin list. skin clone and skin use change the person's files and window, so the agent asks for them as it would for any command. do, when it ships, never goes here: its gate is the Agents row (C45 V16), and the agent's permission prompt shouldn't stand in for it.
  • bNone: every call goes through the agent's own permission prompt. Safe, and the reads become a click each.
  • cEvery word, skin clone and skin use included. Quicker skin loops; the person's skin folder and open window change without a prompt.

Agents that don't read allowed-tools ignore it; nothing else in the skill depends on it.

4 · AS5 · one source

The skill, AGENTS.md and --skill from the same pages

AS5Where it ships, and how AGENTS.md keeps uprecommended a

  • aOne folder in the repo, data/agents/skill/, installed as is to /usr/share/omaseed/agents/skill/ and compiled into the binary. AGENTS.md is generated from it at start: the header, then SKILL.md's body with each "ref:" turned into omaseed skill PAGE. An agent started in ~/.config/omaseed/ loads the same map a skill would, ~600 tokens, and reads a page only when it needs one. A ctest builds AGENTS.md from the folder and checks every "ref:" names a page that is there.
  • bAGENTS.md stays the whole guide (the body and every page, ~2.5k tokens). Nothing to run for a page, and the cwd case loads three times what it needs.
  • cAGENTS.md becomes a pointer: the never list and "read /usr/share/omaseed/agents/skill/SKILL.md". The shortest; one more read every time, and a path that is wrong for a build.

skin.schema.json stays where it is: it is generated from the reader's table at run time, and a clone's $schema names it there. The skill points at that path; omaseed skill link also writes the folder's files once (AS6), so the schema is there before omaseed's first start.

5 · AS6 to AS8 · linking it

One command, asked for, never at start

AS6The commandrecommended a

  • aomaseed skill, a word in C37 U10's family: omaseed skill prints the map, omaseed skill library|skins|files prints a page, omaseed skill link|unlink|status [--json] manage the links. One noun for the whole thing, as skin list|clone|use is for skins. link also writes ~/.config/omaseed/'s guide files once, as a start would. No display, bus or server.
  • bomaseed agents link|unlink|status. Matches the Settings row's name; a second noun beside --skill, and "agents" reads like the gate's setting.
  • cOptions, --link-skill and --unlink-skill, as --install-bar-widget is. U10 turned options down for new commands.

AS7Which folders, and what unlink takesrecommended a

  • aOmarchy's list, so omaseed's skill is wherever Omarchy's are: ~/.agents/skills and ~/.claude/skills always (made if missing); ~/.codex/skills, ~/.pi/agent/skills, ~/.gemini/config/skills, ~/.hermes/skills and each Hermes profile's only when that agent's folder exists. The link is named omaseed. A file or folder of that name that isn't omaseed's link is left and named. unlink removes only links that point at an omaseed skill folder (the installed one or a build's), and leaves the folders it made.
  • bOnly ~/.agents/skills, the shared folder. One link; agents that don't read it (Claude Code today) miss it.
  • cAsk per agent (link --claude --codex). Precise; the person has to know where each agent looks, which is what the command is for.

AS8Who links it, and whenrecommended a

  • aThe person, by asking: the command, and the line on the Agents row. Never at start, never from the package (a package doesn't write in home folders). Where it is offered: the help page's last line ("Coding agents: omaseed skill link, or omaseed skill to read the guide"), omaseed skill's own last line when it isn't linked, the package's install message, and README's agents section.
  • bAs (a), plus a first-run step, as the bar widget has: "Let your coding agent ask omaseed · link · not now". Found by more people; first run is about getting a library, and most people have no agent.
  • cLinked at every start when an agent's folder exists, unlink to stop it. What #286 rules out: files appear in the person's agent setup without being asked.
6 · AS9 to AS11 · prints, upgrades, size

What --skill says, what an upgrade does, how short it stays

AS9What --skill printsrecommended a

  • aThe map, as omaseed skill does: the same text as AGENTS.md without its header, ending with the pages (omaseed skill library, skins, files) and, when no folder has the link, one line naming omaseed skill link. --skill stays as a spelling of it, so C45 V19's help line and older notes keep working.
  • bEverything, as today: the map and every page, ~2.5k tokens. One call, and most of it unread.
  • c--skill goes; only the word. Cleaner, and every place that already says --skill breaks.

AS10Upgrades, and a person who edits itrecommended a

  • aLinks follow the package. An upgrade replaces /usr/share/omaseed/agents/skill/ and every linked agent reads the new one, no step. The installed files are root's, so a person who wants their own guide replaces the link with a copy: omaseed then calls it theirs, leaves it alone, and status says it won't follow upgrades. A removed package leaves dead links behind, which agents skip; the remove message says so and where they are (or run omaseed skill unlink before removing), and installing again brings them back to life.
  • bCopies, not links, headed like AGENTS.md and rewritten at start when they differ. Works for an agent that won't follow a link; it is writing into agents' folders at start, which AS8 turns down.

AS11The size targetsrecommended a

  • aA budget a ctest holds: SKILL.md under 70 lines and 1,000 tokens (counted as bytes / 4), the description under 700 characters, each page under 1,200 tokens. The schema has no budget: it is the reference, reached by grep. The win is the map, not trimming.
  • bTargets written in DECISIONS only. Nothing stops the map from growing back into the manual.

7 · not on this board

Left out, on purpose

  • The trial's product findings: status --json carrying its own pointer to errors, and which surfaces roles.accent paints. Each is a fix in the code, with an issue of its own, not a guide line.
  • Omarchy's own skills folder under /usr/share/omarchy: still Omarchy's (board 55 §8).
  • An MCP server for the same words. The words are already a CLI every agent can run; a server is another thing to keep running.
  • A skill per agent dialect. One SKILL.md; agents that read AGENTS.md in a folder get the same text there.
  • do and its tiers. When the actions ship, the skill gains a "ref: acting.md" page and one line in the map; the gate stays omaseed's (AS4).

9 · building the recommended calls

Five pieces, a patch release

  1. The pages. data/agents/skill/ from today's two parts: SKILL.md as drawn, the three pages, nothing said twice. Installed by data/CMakeLists.txt, compiled as a qrc. The budget ctest (AS11) and the "every ref: is there" ctest.
  2. AgentGuide. map() and page(name) from the qrc; AGENTS.md generated from map() with each "ref:" rewritten; --skill and omaseed skill [PAGE] print through it. Its QtTest grows the new cases.
  3. The links. omaseed skill link|unlink|status [--json] in the words' dispatcher, with a SkillLinker in integration/ (the folder list, "ours" as a link into an omaseed skill folder) and a QtTest on a scratch HOME. The help page's last line.
  4. The row's line, with the Agents row (C45 V16) or on a row of its own if that row isn't built yet. The package's install and remove messages.
  5. The proof. agent-walk.sh gains link, status and unlink on the box's HOME. Then #227's trial again with an agent started in the box's ~, not in ~/.config/omaseed/, with only the linked skill: the two requests, and what it reads. Released alone (C33).
