What an agent may do

Board 62 gave agents a way to read the library (built, v0.14) and ruled a way to act (V14 to V18, not built). Before building that second part, it was tried against a real afternoon: 35 torrents in missing files, their files moved or deleted outside omaseed. An agent with a shell can find where each one went. C45 as ruled can't let it finish: it may never remove a torrent, re-pointing one counts as a move that asks once per word, and the gate is one coarse row. This board amends only those gaps, as GT1 to GT8, and leaves the rest of C45 standing.

1 · the case

35 torrents whose files aren't where the server left them

omaseed errors lists them with kind missing-files and the fixes the window offers: move --to (set location) and recheck. For each, the way out is one of three:

  1. The disk wasn't mounted. It is now, so the files are back where they were: recheck.
  2. The files were moved. They're whole in another folder: point the torrent at that folder, then recheck.
  3. The files are gone. Nothing on any disk: remove the torrent from the list.

The finding is the agent's part, and it's good at it: search the disks for the names errors gave, compare sizes. What C45 lets it do with what it found:

rechecka fix: runs under let them fixnone

removenever (V14)The six dead torrents stay red for ever, or the person removes them by hand one by one.
the gateone row, three chipsSomeone who wants rechecks but no moves, or no agent at all, can't say so.
Is the gate a hard block? No, and it never was. omaseed's gate binds only omaseed's own way in (omaseed do and its bus interface). Anything running as you can call the torrent server's API, the bar widget's D-Bus menu (pause, resume) or edit omaseed's files. A hard block is a rule in the agent's own permission settings, which only you can write. C45 says this in one line; GT7 says it where people will read it, with the rules ready to paste.
2 · GT1 and GT2 · two actions

Remove what's gone, re-point what moved

GT1Removerecommended a

  • aomaseed do remove <hash…>: the torrent only, never its files. No flag deletes files; --delete-files is usage (exit 2), so no wording of a request turns it into a delete. It always asks, whatever the setting allows (GT3 has no allow for it). And omaseed refuses unless that torrent's files are gone: its problem is missing files (kind missing-files, or the engine's own missing state) and, where omaseed sees the disk (a local server or a path map, C14 E11), none of its files is at its save path at the moment of asking. On a server whose disks omaseed can't see, the engine's state alone, and the ask says so. Why: the case's six are already lost; removing them loses nothing, and the guard means an agent can't clear a healthy library through this word.
  • bRemove any torrent, files kept, always asking. More useful (a finished torrent you no longer seed), and one allow clicked without reading takes a working torrent off the list.
  • cKeep V14: never. The case can't finish; the person removes six torrents by hand after the agent has already found them.

GT2Locaterecommended a

  • aomaseed do locate <hash…> --to FOLDER: re-point a torrent whose files are missing at a folder where they are. omaseed first checks that the files are there (each file's relative path and size, as the torrent lists them), then sets the torrent's location without moving anything (Transmission's set-location with move: false; on qBittorrent and Deluge their set-location, which leaves files already at the destination in place; the build proves each on its playground), then rechecks. It's in the fixes tier: nothing on disk changes, and the recheck says whether it was right. Refused when the files aren't all there: locate found 0 of 12 files in /data/shelf-b; also when omaseed can't see that disk, and for a torrent whose files aren't missing (that's a move).
  • bTreat it as move --to: always asks, the move's job and checks (room, names there). The job's room check counts the whole size against a drive the files already sit on, and the person is asked nine times for something that moves nothing.
  • cNo locate. The agent tells the person nine folders and the person types them into nine set-location sheets.

Recommended: GT1 a, GT2 a. Two words that change nothing on disk: one takes a dead torrent off the list and is refused on a live one; the other re-points a torrent only where its files are proved to be.

3 · GT3 and GT8 · what each person allows

One line per kind of act, off until you say

Some people want agents nowhere near their library; some want rechecks run while they're away and nothing else. V16's three chips can't say either. The Agents row already exists (C48: the board's sentence and link the skill); C48 left the gate to join it. This is how it joins.

GT3The Agents row: a line per kindrecommended a

  • aThree lines under the row, one per kind of act. Fixes (retry, start-here, recheck, reannounce, pause, resume, dismiss, locate): off · ask · allow. Moves (move --to, move-back): off · ask, never allow. Remove (GT1): off · ask, never allow. Everything off is read only, the default; the package and the first run never change it. The gate stays in the app (Do on the bus), and do --list prints the three lines as they stand. Three choices cover what people ask for (nothing, rechecks but not moves, ask me for all of it) and keep the dangerous kinds from ever running unasked.
  • bV16 as ruled (read only · ask me · let them fix), with remove behind an ask under the last two. No way to allow fixes and refuse moves, which is the most common wish.
  • cA switch per action (V16 c). Ten actions now, each with three states: thirty choices for a row most people set once. The kinds already sort them by what they can harm.

GT8Reads, for those who want nonerecommended a

Added: the brief's three kinds gate acting only, and V7 keeps reads open with no setting. The maintainer's some people won't want agents near their library at all includes reading it.

  • aA fourth line, first: Reads: on · off. On is the default, so the built reads change nothing. Off, every word (status, errors, log, moves, do) answers not-allowed, exit 5, and the acting lines grey out. Local words (check, skin, help) stay, since they read no library. The line says plainly that this is a courtesy, not a wall (GT7).
  • bKeep V7: reads always open. Simpler, and a person who wants none has only the agent's own settings.
set to

Recommended: GT3 a, GT8 a. Four short lines: reads on or off, then fixes, moves and remove, each as far as you want and no further. Nothing is on for acting until you turn it on, and two kinds can never run unasked.

4 · GT4 and GT5 · many at once

Say the whole plan first, then one ask

GT4One ask for manyrecommended a

  • aomaseed do --plan FILE|-: a JSON list of lines, each an action, its torrents and, for locate and move, a folder. omaseed checks every line first (the setting, GT1's guard, GT2's find); if any line is off or refused, nothing runs and the answer says which. Otherwise, if any line asks, one window lists the whole plan grouped by action and folder: the lines the setting already allows dim, marked allowed in Settings; the lines that ask with a checkbox each, ticked. allow these runs the plan with what's ticked; refuse (or esc, close, 2 minutes) runs none of it. The answer lists done and failed per line. Every line is checked again just before it runs, so a dry run's answer can't go stale into a wrong act.
  • bOne ask per word (V17 today). Fifteen windows for the case, the tenth one clicked without reading.
  • cAllow everything for this session in the first window. One click hands over the rest of the afternoon, moves and removes included.

GT5Say first, then dorecommended a

  • a--dry-run on every do and --plan: every check runs (the setting, the guard, locate's find), nothing asks and nothing acts. It says what would happen line by line (locate found 12 of 12, remove: its files are gone; the list loses it, would ask) and exits as the real run would, minus the ask: 0 when every line would run or ask, 5 when one is off or refused. An agent can show the person the plan in the terminal before a window ever opens.
  • bNone. The agent learns a line was refused only by trying it, and the person meets the plan first in the window.

Recommended: GT4 a, GT5 a. The agent writes what it found as one plan, checks it dry, and asks once. You see the whole of it in one window, and untick what you'd rather keep.

5 · GT6 and GT7 · after, and around

A way back, and the wall that isn't omaseed's

GT6A way back after a removerecommended a

  • aKept 30 days. Before a remove, omaseed saves the torrent's .torrent (the same export Backup uses) and its record (name, save path, category or labels, tags, the server) under ~/.local/share/omaseed/removed/; a start prunes what's older than 30 days. The outcome strip says Removed 5 · by an agent · add back, and the Agents row's last line keeps add back… while any are kept: a sheet listing them, each added back paused at its old place (you might have found the files). Adding back is the person's, in the window; do never adds (V14).
  • bNothing. The files are gone anyway; but the torrent was the way to fetch them again, and a magnet or the file may be hard to find later.
  • cKeep them for ever. A folder that grows unseen, for torrents removed because they were dead.

GT7The hard block, said plainlyrecommended a

  • aSay it where it's read, and hand over the rules. The Agents row's reads line and the guide say that the gate binds only omaseed. omaseed help agents prints ready-made deny rules for the agents omaseed links its skill for (C48), filled in with the server on show's address: no calls to the torrent server's port; no busctl/gdbus on omaseed's bus name (omaseed's own words reach it without either); no edits to omaseed's files except skins/ and layouts/. People paste them; omaseed prints and never writes them. It also says what such rules are: pattern matches on commands, which a determined script can step around; an agent's sandbox with a network allow list is the wall.
  • bNothing more than C45's one line. True, and nobody reads it where they set the gate.
  • comaseed writes those rules into each agent's settings itself. Rejected: writing another app's settings (C48 links a skill folder and stops there).

Recommended: GT6 a, GT7 a. A removed torrent can come back for a month. And omaseed tells you, where you set the gate, that the real wall is your agent's, with the rules to build it.

7 · what it changes in C45

Six rulings amended, the rest standing

  • V7 (GT8): reads stay open by default, behind a line that can turn them off.
  • V14 (GT1, GT2): the fixes gain locate; a third kind, remove, the torrent only and only when its files are gone, always asking. Never still holds for deleting files, rename, categories, tags, adds, settings, servers and quit.
  • V15 (GT2, GT4, GT5): do gains locate --to, remove, --plan FILE|- and --dry-run. Torrents stay hashes or 8-character prefixes. V13 gains the failure code not-removable (exit 5) and locate's not-found (exit 5); its numbers don't change.
  • V16 (GT3, GT6): the three chips become four lines on C48's Agents row (reads; fixes off · ask · allow; moves off · ask; remove off · ask), all acting off by default; the last line keeps add back… while removed torrents are kept.
  • V17 (GT4): one ask may hold a whole plan, with a box per line that asks; refusing refuses all of it.
  • V18 stands: · by an agent on every act, a plan's outcome too. C45's preamble on the gate gets GT7's words and omaseed help agents.
  • C48: the skill's never list keeps do out of allowed-tools; its library page gains missing files: errors, find, plan, dry run, one ask.
