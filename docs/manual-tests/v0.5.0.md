([46](../46-the-whole-app-on-v03.html), DECISIONS C24) and adds search (board

## Setup (about 10 minutes)

Two terminals: **host** is a terminal in this checkout; **box** is a terminal inside the box
(**SUPER+RETURN** there), so what it changes is the box's, never yours.

```sh
# host
scripts/dev/manual-box.sh          # a throwaway desktop, a window on workspace 9, omaseed from this checkout
scripts/dev/move-library.sh        # moves.md's library in "public": 109 torrents under /home/sbx/library, and /tmp/fast
H="$(omabox path -b manual-box)/home"                       # the box's HOME, seen from the host
python3 -I scripts/dev/search-plugins.py make "$H/search-plugins"   # four invented search plugins, for section 5
```

In the box: click into the window, **SUPER+ALT+ESC** (SUPER keys go to the box; again to give them
back), **SUPER+SPACE**, `omaseed`. First run finds "public" on `127.0.0.1:8090`; both logins are in
the box's `~/qbittorrent-login.txt` (also printed by `manual-box.sh`). Let first run register the
links (its "links" step): section 7 opens a magnet. Then **,** › Servers, **a**: add "private"
(`127.0.0.1:8091`, its login). It is downloading four small torrents and seeding Sketchbook
Scans (v1); they finish in a minute or two. A box is a new install, so the library starts on the
**rows** display (C24 H4).

For create (section 6), in **box**: folders of made-up files, and a big sparse one that takes a
few seconds to hash.

```sh
# box
mkdir -p ~/share/field-recordings ~/share/photo-walks/harbour ~/share/big-archive
for n in 1 2 3 4; do head -c 1M /dev/urandom > ~/share/field-recordings/"0$n take.flac"; done
for n in 1 2 3; do head -c 2M /dev/urandom > ~/share/photo-walks/harbour/walk-0$n.jpg; done
echo "a walk by the harbour" > ~/share/photo-walks/notes.txt
echo "hidden" > ~/share/photo-walks/.DS_Store
truncate -s 24G ~/share/big-archive/disk.img
```

And in **host**: an invented private tracker with a passkey on one of private's torrents, so
create's private path has a host to offer (the URL never leaves the box; nothing answers it):

```sh
# host
hash="$(scripts/dev/app-box.sh api -b manual-box --server private torrents/info | python3 -c 'import json, sys; print(next(t["hash"] for t in json.load(sys.stdin) if t["name"] == "tiny-notes.txt"))')"
scripts/dev/app-box.sh api -b manual-box --server private torrents/addTrackers \
  --data-urlencode "hash=$hash" --data-urlencode "urls=https://tracker-a.example/announce/manualpass0c0ffee"
```

Moving things: a torrent that stays **arriving** for a while needs a slow seeder. When a step asks
for it, in **host**: `scripts/dev/swarm.sh rate 256` (the swarm's seeder at 256 KiB/s), and
`scripts/dev/swarm.sh rate 4096` to put it back.

**Themes and sizes.** Run the sections on the box's own theme, then go back over the frame, the
library and details on at least one light and one dark theme, in **box**:
`omarchy-theme-set catppuccin-latte` (light), `omarchy-theme-set flexoki-light` (light),
`omarchy-theme-set tokyo-night` (dark), `omarchy-theme-set everforest` (dark, its fills capped,
C30). A narrow window: **SUPER+RETURN** opens a terminal beside omaseed (half the width); with
omaseed focused, **SUPER+-** and **SUPER+=** take 100 px off or give it back, down to the
window's floor. A large base size: section 8.

Each step: what to do, then what you should see. Note OK, or what you saw instead. Each box is

## 7. The magnet that waits for its file list (#193; docs/29 F4)

qBittorrent 5.3.0 crashed when a magnet was added while its file list was still being fetched.
omaseed now holds the add until the list is in, or a minute has passed.

1. **Held.** On public, delete the sampler with its files (**D**) if it is there. In **host**:
   `scripts/dev/swarm.sh break stall` (the seeder stops sharing, so no list comes). In the box,
   open `~/Downloads/links.html` in Chromium (or Files) and click the sampler's magnet; or in
   **box**: `xdg-open "$(grep -o 'magnet:[^"]*' ~/Downloads/links.html | sed 's/&amp;/\&/g')"`.
   The add sheet: "Asking qBittorrent for the file list". Press **enter** at once. The sheet
   stays; the Files row says your add goes out as soon as the list is in, or after a minute
   without one, because adding while qBittorrent fetches can crash qBittorrent 5.3.
2. **The list arrives.** Within the minute, in **host**: `scripts/dev/swarm.sh fix`. The list
   comes in and the add goes by itself; the sampler is in the library, downloading. In **host**:
   `scripts/dev/app-box.sh api -b manual-box app/version` still answers (qBittorrent is up).
3. **The minute.** Delete it again, `scripts/dev/swarm.sh break stall`, open the magnet, enter,
   and wait: at a minute "The file list may never come", and the held add goes as before (every
   file). Then `scripts/dev/swarm.sh fix`.
4. **Closed while held.** Again with the seeder stalled: open the magnet, enter, then **esc** the
   sheet. `scripts/dev/swarm.sh fix`: the add still goes once the list is in.

(`swarm.sh fix` also restarts the playground's swarm torrents on `:8081`; nothing here uses them.)
